# TED-SWS Docker Stack

Unified Docker Compose setup for the TED-SWS infrastructure.

## Architecture

The stack runs 8 user-facing services plus internal infrastructure (Postgres, Redis) behind
a Traefik reverse proxy. Two Docker networks isolate traffic:

- **tedsws-proxy-net** -- services exposed via Traefik (web UIs, APIs)
- **tedsws-internal** -- backend communication (Airflow workers to MongoDB/Fuseki/MinIO, Redis, Postgres)

Airflow uses CeleryExecutor with Redis as broker and Postgres as metadata DB. The scheduler,
worker, triggerer, and webserver all share the same image (`tedsws/airflow:local` for local,
`tedsws/airflow:staging` for staging).

Configuration is layered: a base `docker-compose.yml` defines service structure with `${VAR}`
placeholders, and environment-specific override files add ports, volumes, build config, and
labels.

## Quick Start

```bash
# Start all services
make start-local-stack

# Start specific services only
make start-local-stack SERVICES="mongodb fuseki minio"

# Stop the stack
make stop-local-stack

# Stop and remove all data, volumes, images, and build cache
make cleanup-local-stack

# View logs
docker compose -p ted-sws-stack logs -f
```

## Files

| File | Purpose |
|------|---------|
| `docker-compose.yml` | Base config -- service structure, `${VAR}` for passwords |
| `docker-compose.local.yml` | Local overrides -- build, volumes, ports, Traefik labels |
| `docker-compose.staging.yml` | Staging overrides -- host paths, TLS, labels |
| `docker-compose.local-nodata.yml` | Ephemeral mode -- no persistent volumes |
| `.env.common` | Shared app configs -- hostnames, ports, tool paths (committed) |
| `.env.local` | Local passwords and connection strings (committed, safe defaults) |
| `.env.staging` | Staging passwords from Vault (generated by `make staging-unified-dotenv`) |
| `airflow/Dockerfile` | Airflow image with celery provider |
| `airflow/requirements.txt` | Python dependencies for Airflow |

## Environment Configuration

Environment variables are layered using multiple `env_file:` directives in compose overrides.
Later files override earlier ones.

**Local:**

```yaml
env_file:
  - .env.common    # shared non-secret configs (hostnames, ports, tool paths)
  - .env.local     # local passwords + connection strings
```

**Staging:**

```yaml
env_file:
  - .env.common    # same shared configs
  - .env.staging   # Vault passwords + staging-specific overrides
```

The `.env.common` file is shared across all environments. Only passwords and
environment-specific values differ between `.env.local` and `.env.staging`.

No Vault access is needed for local development.

### Staging Secrets

Staging passwords are stored in Vault at `ted-staging/ted-sws-deployment-secrets` (9 keys).
Run `make staging-unified-dotenv` to generate `.env.staging` from Vault.

## Ephemeral Mode

For debugging "works on my machine" issues, run without persistent data:

```bash
make start-local-stack-nodata

# Also supports selective services
make start-local-stack-nodata SERVICES="mongodb fuseki"

# Stop with the same command
make stop-local-stack
```

All data is lost when containers stop.

## Adding Dependencies

1. Add to `requirements.txt`
2. Rebuild: `make start-local-stack` (rebuilds automatically)

## Volume Data

The stack uses named volumes for persistent data:

- `minio-data`
- `mongodb-data`
- `fuseki-data`
- `sftp-data`
- `airflow-postgres-data`

To reset everything (volumes, images, build cache):

```bash
make cleanup-local-stack
```

To remove specific volumes manually:

```bash
make stop-local-stack
docker volume rm minio-data mongodb-data fuseki-data sftp-data airflow-postgres-data
make start-local-stack
```

## Migration from Old Setup

### Before (old way)

```bash
make start-traefik
make start-mongo
make start-fuseki
make start-minio
make build-airflow
make start-airflow
make start-metabase
make start-sftp
```

### After (new way)

```bash
make start-local-stack
```

### Command Mapping

| Old Command | New Command |
|-------------|-------------|
| Multiple `make start-*` | `make start-local-stack` |
| Multiple `make stop-*` | `make stop-local-stack` |
| Manual volume/image cleanup | `make cleanup-local-stack` |
| `make init-rml-mapper && make init-limes && make init-saxon` | `make init-libraries` |
| `make staging-dotenv-file` | `make staging-unified-dotenv` |

### Key Differences

1. **Single command** -- all services start together with proper dependency ordering.
2. **Layered env files** -- `.env.common` (shared) + `.env.local` / `.env.staging` (secrets).
3. **Own networks** -- `tedsws-proxy-net` and `tedsws-internal` (old setup uses `proxy-net`, `common-ext-${ENVIRONMENT}`).
4. **Simplified container names** -- `airflow-worker`, `mongodb`, `fuseki` (no environment suffix).
5. **Local Airflow image** -- built as `tedsws/airflow:local` instead of `meaningfy/airflow:latest`.
6. **Consolidated Vault** -- single path `ted-staging/ted-sws-deployment-secrets` (9 keys) instead of 7 separate paths.

The old individual service targets are **not removed** and can still be used if needed.

## Troubleshooting

**Services not accessible via *.localhost URLs?**
- Ensure Traefik is running: `docker ps | grep traefik`
- Access directly via ports instead (e.g., http://localhost:8081 for Airflow)

**Airflow worker keeps restarting?**
- Check logs: `docker logs airflow-worker`
- Ensure celery provider is installed (check Dockerfile)

**Permission issues with mounted volumes?**
- Run `sudo chown -R $USER:$USER libraries/`

**Port conflicts with old containers?**
- Ensure old containers are stopped before starting the unified stack:
  `docker ps | grep -E "traefik|mongo|fuseki|minio|airflow|metabase|sftp"`

**DAGs not loading?**
- Check volume mounts: `docker exec airflow-scheduler ls /opt/airflow/src/dags`

**Stale import errors in Airflow UI?**
- Clear cached errors: `docker exec airflow-webserver airflow db clean --clean-before-timestamp "$(date -I)" --tables import_error -y`
